# Faster live delta comparison

2026-10-30. This reduces CPU metadata work in `onggi diff --ranges --json`,
used before resident NPU updates. It does not change device execution.

## Cause and change

Profiling the immutable Llama-3.1-8B sparse-projection and sparse-LM fixtures
found 332–365 ms in the CLI comparison and 6–13 ms in Python row planning.
`Store.Diff` planned the target twice: `Extents` decoded/validated its metadata,
then `Diff` repeated that work for unique new stored-byte accounting.

The target plan is now built once and its nodes serve both computations.
There is no cache across calls. Ref resolution, metadata digest validation,
missing-pack/index fallback, extent sorting and public JSON remain unchanged.
This applies to any artifact kind, including ATOM and RNGD files; the measured
fixtures below are safetensors, not opaque compiled vendor files.

## Same-toolchain comparison

Baseline `05c97605b07882f9ceaaeb90b94878f8923f81cf`; measured candidate binary
`216df102436cce459fc76de9407661f548896490`. Later changes only add the benchmark,
sort test imports and record results; the production source SHA is checked.
Both binaries use Go 1.27.3 linux/amd64, `-trimpath`, GOMAXPROCS=4 and the same
existing POSIX store on the shared 96-logical-CPU host. Six pairs per direction
alternate which build runs first. Every sample, including the first, is kept.
The filesystem is warm; host scheduling is uncontrolled and no cold-cache
experiment or statistical significance claim is made.

| Direction | Baseline median | Candidate median | Reduction |
| --- | ---: | ---: | ---: |
| base -> projection rows | 295.213 ms | 269.595 ms | 8.68% |
| projection rows -> base | 287.708 ms | 248.118 ms | 13.76% |
| base -> LM rows | 284.904 ms | 248.444 ms | 12.80% |
| LM rows -> base | 282.935 ms | 259.438 ms | 8.30% |

All **48 CLI outputs** are byte-identical between builds and repetitions for
their ref pair. This checks every file/range and same/moved/new/stored byte
count. [Every sample, binary/source hash, ref digest and validation result](data/diff-plan-20261030.json).
These numbers isolate the CLI stage. NPU loading, token parity, full-update
latency and S3 performance were not remeasured by this CPU experiment. Prior
[resident NPU measurements](https://github.com/ai-computing/rngd-pd/blob/0bc244db0239bddfdda005454809aee0812877d8/experiments/2026-10-30-rngd-sdk264.md)
retain their original scope; do not subtract these savings from them as a new
end-to-end measurement. The diagnostic CLI timings used the existing binary,
so they are not the controlled speed comparison above.

## Verification

The access-bound regression first failed with two target-locator reads, then
passed with one. Additional checks preserve legacy/no-locator comparisons,
identical/empty artifacts, changed/rearranged chunks, corrupted-target rejection
and diff after GC repack removes stale locator packs. Linux `go test -race
./...`, `go vet ./...` and `gofmt -l` pass. A fresh read-only review found a
test import ordering issue; it was fixed and the gates rerun. Cancellation
guarantees are unchanged and not newly established: they depend on backend I/O,
and existing CPU extent/stat loops have no explicit cancellation checkpoints.

No NPU was allocated. The toolchain, source builds, logs and caches were placed
in an owned experiment directory; no shared SDK/driver or original provider
checkout was modified. The public record removes machine paths and retains
SHA256/lengths of the seven original exported files.

## Reproduce

Build both revisions with the same toolchain into separate paths and use an
immutable store/ref pair:

```bash
git -C "$REPO" worktree add "$BASE_TREE" 05c97605b07882f9ceaaeb90b94878f8923f81cf
git -C "$REPO" worktree add "$CAND_TREE" 216df102436cce459fc76de9407661f548896490
go -C "$BASE_TREE" build -trimpath -o "$BASE_BIN" ./cmd/onggi
go -C "$CAND_TREE" build -trimpath -o "$CAND_BIN" ./cmd/onggi
python3 bench/diff.py "$BASE_BIN" "$CAND_BIN" "$STORE" base sparse > comparison.json
```

The harness fails if parsed diff output changes across any build or repetition;
it reports CLI wall time including process startup, not only `Store.Diff` CPU
time. Reversing refs checks the reverse transition separately.
